# Workshop Audit — 2026-07-03

Full-codebase review of `devys-workshop` covering all 14 projects, shared libraries, scripts,
and infrastructure. Five parallel review passes (core infra, evolution/sim, media pipeline,
trading + server dashboard, splitwiser + misc) synthesized here. Findings marked **[verified]**
were manually re-checked against source; the rest come from the review pass with file:line
citations.

---

## 1. Workshop overview

**Shape:** one Next.js 15 / React 19 app (App Router), ~27k LOC TS, 17 page routes, 60 API
routes, Postgres 16 with three scoped roles (`workshop`, `soulseek_ingest`, `challenge_poller`),
forward-only hash-tracked SQL migrations, systemd timers for collectors
(quotes, system metrics, heavy metrics, challenge poller, soulseek ingest), one Python GA
submodule (`vendor/brainfuck-genetic`) driven over JSON-lines stdout.

**General health:** strong. The big projects (BrainFuck GA, Paper Trading, Polar Clock,
Server Dashboard, Soulseek) are genuinely polished. Money is BIGINT cents everywhere,
order fills use `FOR UPDATE` transactions, the BF event chain is serialized correctly,
metrics v2 uses parameterized `date_bin` SQL. The weak spots cluster in four themes:

1. **A handful of real, live bugs** (two features silently broken, one file-deletion traversal)
2. **No auth on destructive/privileged endpoints** (acceptable-on-LAN, but worth a cheap gate)
3. **Copy-paste drift** — the same helpers/lists/logic duplicated 2–4× across files
4. **Main-thread sim loops** that would benefit from Workers/typed arrays as they grow

## 2. Live bugs — fix first

### 2.1 `/api/challenges/sync` reads a config schema that no longer exists **[verified]**
`src/app/api/challenges/sync/route.ts:38-41` does a raw `fs.readFile(config.json)` and
destructures flat keys (`riotApiKey`, `riotGameName`, …). The real config is nested
(`riot.apiKey` — confirmed against the live `config.json`). **The manual sync button
returns 500 "Riot API not configured" today.** Fix: use `getConfig().riot` from
`src/lib/config.ts`. (S)

### 2.2 `/api/settings` writes the same dead flat schema **[verified pattern]**
`src/app/api/settings/route.ts` GET/PATCHes flat keys (`riotGameName`, `musicDirectory`)
that `getConfig()` never reads — and it's completely unauthenticated. Effectively a broken
legacy endpoint. Fix: delete it (callers should use `/api/config`, which is properly
token-gated). (S)

### 2.3 Arbitrary file deletion via DELETE `/api/soulseek/ingest` **[verified]**
`src/app/api/soulseek/ingest/route.ts:171-174`:
```ts
for (const filePath of files) {
  await fs.unlink(path.join(DOWNLOADS_DIR, filePath)).catch(() => {});
}
```
`files` comes straight from the request body — `{"files": ["../../../home/server/x"]}`
deletes outside the downloads dir. Fix: `path.resolve` + `startsWith(DOWNLOADS_DIR + sep)`
guard before unlink. (S)

### 2.4 Soulseek "Connected" badge always shows Disconnected **[verified mismatch]**
`src/app/projects/soulseek/page.tsx:1336` reads `d.server?.isConnected`, but
`/api/soulseek/status` passes through the raw slskd `/api/v0/application` response, which
the route itself types as `{ state, version }`. Check the actual slskd payload and align
one side. (S)

### 2.5 Splitwiser leaks the bearer token on every page load **[verified]**
`getCurrentUser()` uses `RETURNING *` (`src/lib/splitwiser-auth.ts:28`) and `/api/splitwiser/me`
returns `{ user }` verbatim — including `login_token`, the permanent credential. The home
page calls `/me` on every load, so any XSS anywhere on the site harvests a 1-year token.
Signup and `login/[token]` responses leak it too. Fix: `toPublicUser()` helper that strips
`login_token`; serve the QR/login URL from a dedicated settings-only endpoint. (S)

### 2.6 BarFoo 56px header offset **[per project convention]**
`src/app/projects/barfoo/page.tsx:713` uses `calc(100vh - 56px)`; convention is **57px**
to avoid the phantom scrollbar. (S)

## 3. Security posture

Context: LAN-only personal server, so "no auth" is a deliberate tradeoff — but these are the
places where that tradeoff has teeth:

| Endpoint | Risk | Effort |
|---|---|---|
| `DELETE /api/soulseek/ingest` | arbitrary file deletion (§2.3) | S |
| `POST /api/server/services` | anyone on LAN can stop/restart any service (incl. minecraft, workshop) | S–M |
| `POST /api/server/rcon` | unauthenticated RCON to game servers | S |
| `POST /api/setup/probe/[service]` | unauthenticated probes using stored credentials | S — reuse `X-Setup-Token` gate from `/api/config` |
| `/api/settings` | unauthenticated config writer (also dead — delete it) | S |
| Paper trading accounts | `DELETE /accounts/:id` wipes a ledger, `seedDollars` uncapped | S |
| Splitwiser `payments/[id]` DELETE | missing group-membership check (expenses route has it — `expenses/[id]/route.ts:33`) | S |
| `ingest.sh` SQL via sed-escaping | shell/SQL injection surface if a torrent name is hostile (`scripts/jellyfin/ingest.sh:113-155`) | M |

**Cheapest meaningful win:** a tiny shared `requireLocalOrToken()` middleware helper applied
to the ~10 destructive endpoints. It doesn't need to be a full auth system.

Splitwiser fundamentals are otherwise sound: 256-bit tokens, httpOnly + SameSite=lax cookies,
parameterized SQL throughout, membership checks on expense routes.

## 4. Cross-cutting code quality

### 4.1 Duplication map (consolidation targets)
- **`fmtBytes`/`fmtSpeed`/`fmtTime`/`fmtEta`** — jellyfin page (:106-148), soulseek page (:126-154), server services page (:62), history `align.ts:59` → `src/lib/format.ts`
- **`ProgressBar` + `ConnectionBadge`** — byte-identical in jellyfin (:187-209) and soulseek (:198-215) pages → `src/components/ui/`
- **slskd transfer flattening** — 4 copies (`ingest-downloads.ts` ×2, downloads route, uploads route, transfers stream) → export from `src/lib/slskd.ts`
- **`ingest-downloads.ts:41-47`** reimplements `slskdGet` inline instead of importing it
- **Service name lists** — `TRACKED_SERVICES` (services route), `ALLOWED_SERVICES` (logs route + logs/stream route, identical copies), `PINNED_LABELS` (process-explorer.tsx:146) — four files to edit per new service → one `src/lib/server-services.ts`
- **Challenge sync upsert logic** — `scripts/sync-challenges.ts:64-91` ≈ `api/challenges/sync/route.ts:65-141` ≈ `poll-challenges.ts:182-190` → `src/lib/challenges-sync.ts` (also fixes §2.1 as a side effect)
- **`fmtMoney`/`todayISO`** — 3 splitwiser copies
- **HTTP client wrappers** — `slskd.ts`, `transmission.ts`, `riot.ts` each roll their own fetch wrapper with different (mostly absent) timeout behavior

### 4.2 Missing timeouts on outbound HTTP
Only Finnhub (`quotes.ts:71`) uses `AbortSignal.timeout`. Riot, slskd, transmission, and the
ingest daemon have none — a hung external API freezes the challenge-poller/ingest systemd
services indefinitely. Add `AbortSignal.timeout(8-15s)` everywhere (or via the shared fetch
wrapper above). **Highest-impact safety fix in the whole audit.** (S)

### 4.3 Other infra items
- `db.ts` pool has no explicit `max`/`connectionTimeoutMillis` — exhaustion hangs silently rather than erroring (S)
- `riot.ts:44` rate limiter computes waits from a stale `now` captured before the loop (S)
- `MARKET_HOLIDAYS` runs out after 2027 — add a startup/test assertion that it covers now+12mo (S)
- `next.config.ts:8` `eslint.ignoreDuringBuilds: true` — flip once warnings are cleaned (M)
- Legacy `/api/server/metrics` + `/metrics/multi` (JS-side bucketing over the old `system_metrics` blob table) appear unused now that v2 exists — delete (S)
- No metrics retention: `metric_system_cpu` at 15s/row grows unbounded — add a prune job (90d) (S)
- Music/album thumbnails stored as base64 data-URIs in Postgres — ~1.6MB+ inline per `/api/music` cold load; move to a covers dir or `/api/music/cover` route (L)
- `/api/music/stream` does `fs.readFile` of the whole file (even for Range requests) — a big FLAC spikes heap per listener; use `fs.createReadStream({start,end})` (M)
